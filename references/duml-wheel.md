# 第三个拨轮：只在 DUML 里，不在 evdev 里

> 实测机型：DJI RC Plus 1（RM700B，`ro.product.model=DJI RC Plus`，
> `ro.board.platform=kona`，Android 10）。2026-11-15 验证。

## 结论先说

遥控器上**右拨轮正下方**还有一个滚轮，它**不回中**（拧到哪停在哪）。
它**不在 `/dev/input` 的任何节点里**，但**一直在 DUML 协议里正常上报**。

所以：

- `getevent -lp` 找不到它 ≠ 硬件没装 ≠ 固件不支持
- 这个轮子**不需要接线、不需要拆机**，现在就能读
- 上报路径是 DJI 私有的 `0x06/0xAE` 状态包，第 4 个字节（`byte 4`）

## 为什么 evdev 这条路上肯定没有

```
/dev/input/event6  "DJI embedded joystick"
  B: EV=20000b        → SYN(0) + KEY(1) + ABS(3) + FF(21)
  ABS_X / ABS_Y   ±32767    左摇杆
  ABS_RX / ABS_RY ±32767    右摇杆
  ABS_Z  / ABS_RZ 0..255    左右两个自回中拨轮
  ABS_HAT0X / HAT0Y -1..1   五向键
```

关键在这个 `EV=20000b`：**没有 `EV_REL`（第 2 位）**。

Linux 输入子系统里，"不回中的滚轮"的标准上报方式是 `EV_REL / REL_DIAL`
（拧一格报一次 +1/-1，没有"位置"概念）。event6 连这个能力位都没声明，
说明内核侧压根没注册这一路。另外 `ls /dev/hidraw*` 为空 ——
也没有绕开 evdev 的独立 HID 通道。

## DUML 怎么读

### 1) 打隧道

`40007` 是遥控器自己 loopback 上的端口（`LISTEN, uid 0`），必须从 PC 侧转发：

```bash
adb forward tcp:40007 tcp:40007
```

### 2) 帧格式

```
55 CC 30 75 | uint32 LE 载荷长度 | 载荷
```

载荷里：

| 偏移 | 含义 |
|---|---|
| 9 | cmd_set = `0x06` |
| 10 | cmd_id = `0xAE` |
| 11..27 | 17 字节状态数据 |

### 3) 必须发心跳，否则会被踢

每 **40ms** 一个 keepalive（cmd_set `0x00` / cmd_id `0x01`，app(2) → RC(6)），
带 CRC8（头）和 CRC16（整体）。不发的话 DJI 的协议服务会关掉连接。
两个客户端同时连没问题（可以一边跑 DJI App 一边读）。

### 4) 17 字节状态包结构

| 字节 | 含义 |
|---|---|
| 0, 1 | 固定 `00 00` |
| **2** | mode / back 键 |
| 3 | 固定 `00` |
| **4** | **滚轮 ← 就是它** |
| 5..6 | 右摇杆 X（int16 LE，中心 1024） |
| 7..8 | 右摇杆 Y |
| 9..10 | 左摇杆 Y |
| 11..12 | 左摇杆 X |
| 13..14 | 左拨轮 |
| 15..16 | 右拨轮 |

六个轴都是 **int16 LE，中心 1024，满行程约 ±660**。
所以一个"静止"的状态包长这样：

```
00 00 02 00 00 | 00 04  00 04  00 04  00 04  00 04  00 04
                    ↑ 六个 0x0400 = 1024
```

### 5) 滚轮字节的编码

| bit | 含义 |
|---|---|
| 7 | 转动中（静止时整字节为 `0x00`） |
| 6 | 方向（1 = 屏幕上的 ▶ / 右，0 = ◀ / 左） |
| 5..1 | 速度档 1~5（实测能拨到 4；边沿会出现 0） |
| 0 | 恒为 0 |

实测取样：

```
0x82 → 左 1 档      0xC2 → 右 1 档
0x84 → 左 2 档      0xC4 → 右 2 档
                    0xC6 → 右 3 档
```

**方向已由用户实机确认**：`0xC*` 确实对应手往 ▶ 方向拧。

## 刷新率

| 状态 | 实测 |
|---|---|
| 静止 | **9.7 包/秒**（约 100ms 一个） |
| 拨动时 | 设备**立刻补发**状态包，相邻变化最短 **20ms** |

所以它不是"100ms 才反应一次"，而是事件驱动的。做输入用足够。

## 和 RC Plus 2 的关系

RC Plus 2（TKPL2）的同类项目里，`byte 4` 就是右上滚轮 —— 位置、编码完全一致。
也就是说 RC Plus 1 的固件**也实现了这一路**，只是没往 evdev 里映射。

## 踩过的坑

1. **索引别数错**：`p` 是 `bytes`，`byte 4` 是 `p[4:5]`；
   如果误当 hex 字符串去切 `p[8:10]`，抓到的是左杆 Y 的噪声，
   会看到满屏假变化（真踩过，浪费了一轮录制）。
2. **adb server 重启后 forward 会丢**，报 `no devices/emulators found`。
   无线串号要顺手补一次 `adb connect <ip>:5555` 再 forward。
3. **端口 40007 可能被上一次运行的残留占着**（`cannot bind: 10048`）。
   这时不要慌 —— 连上去照样能用，说明已经有一条到同一台机器的隧道。
4. **不要用 `pkill -f getevent` 清理**，会把自己那个 shell 一起杀掉。
   正确做法：
   ```bash
   ps -A -o PID,ARGS | grep 'getevent -lt' | grep -v grep | \
     awk '{print $1}' | xargs -r kill -9
   ```

## 还没做

这个轮子目前**只显示，不参与手柄输出**。原因是 Xbox 360 虚拟手柄的
六个轴已经排满了（两摇杆 + 两拨轮占 LT/RT），要给它一个轴就得征用别人的位置。

可选方案（真要接的话）：

- **鼠标滚轮**（`SendInput` MOUSEEVENTF_WHEEL）：不占手柄资源，语义也最自然
- **按键脉冲**：一格发一个键，适合 turtle mode / 重置 / 切视角
- **位置轴**：累积成 0~100 的滑块，但得占掉 LT 或 RT 之一
